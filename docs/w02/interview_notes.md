## 提取方法开发与验证

**路线**：路线一（修改课程工具）。沿用课程的提取、来源检查、人工停点与记录保存，只改本客户的任务与提示词，未改通用 Skill 和 Python 代码。

**本轮材料的特点与处理要求**：本周受访者大量使用“不掌握／说不准／要查记录”，并频繁把问题转给他人，还常对自己的话加限定（“只是例子”“不是公司口径”“不代表已交付”）。这些正是业务模型需要保留的未知、转介和限定，因此处理要求是：一条候选只对应一位受访者；未知要写明核实对象；转介要写明转给谁；受访者的自我限定不能丢；流程步骤和清单要逐项保留。

**方法改动（`customer/w02/`）**：
- `workflow.json`：`goal` 写明本轮要核实的对象划分、口径负责方、职责交接、试点边界，并保留分歧、未知、转介。
- `extraction.json`：6 条 `focus_questions`（对象划分、口径与负责方、职责与交接、试点范围与授权、旧项目分歧、转介关系）；`batch_chars` 16000→6000；`profile` compatible→json-object。
- `extraction_prompt.txt`：在课程原有 4 条规则后追加 5 条（主体单一并标注 role_id；未知＋核实对象；转介＋对象；保留自我限定；步骤与清单逐项保留、复述确认可作补充证据）。

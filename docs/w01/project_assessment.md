## 6. 下一阶段建议与承诺边界

**建议进入 W02，开始前提**

1. 老周：提供数据源清单与一份脱敏样本（会员、订单、门店，至少覆盖两个连续自然月）。
2. 小林：一次访谈，说明当前圈选重点会员的方式、阈值和交付格式。
3. 沈总：确认复购率口径和可接受的验证节奏。

**下一阶段先验证什么**：在独立实例导入青禾脱敏样本，复跑下降人群识别与建议，由小林评估建议可用性；同时由小林/老周核对名单与金额。

**第一阶段范围（沈总已认可，MSG-00671）**：助手只给小林看名单和建议，不直接打标签、发券或修改青禾系统。

**继续投入的标准**：沈总目前“给不了量化标准”，拍板人与审批流程未定（MSG-00671）。W03 须与沈总、王经理共同确定：识别准确性与建议可用性达到什么程度算通过、由谁决策、董事会何时听取进展，并写入 SOW；在此之前不以任何效果数字作为第一阶段验收。

**调整或暂缓条件**：数据在 W03 前无法取得或无法合法脱敏；复购口径无法达成一致；小林确认现有流程不需要该环节；W03 前无法就继续投入的标准与决策人达成一致。

**当前不承诺**：复购率提升数字及三个月见效；80 万会员全量接入时间；对青禾系统的任何写操作（打标签、发券，GAP-009）；生产部署、多用户与审计。

## 7. 工程备注

- 实现路线：官方产品 `0.2.0-w1`，Python 3.11.12，Windows 11。
- 模型：`gemini-3.8-flash`，协议 chat_completions，提示词 SHA-256 `051286bc…fddd`，数据版本 `sample-1`。
- 模型适配：Gemini 提供 OpenAI 兼容端点，使用 `FDE_MODEL_PROFILE=compatible`，未修改适配器代码。
- Promptfoo 评估：2026-10-21 用 promptfoo 0.122.2、`--no-cache` 运行 7 个场景，7 通过、0 失败、0 错误，耗时 8 分 1 秒，共 52,405 tokens（`artifacts/w01/promptfoo-results.json`）；`tools/finalize_evaluation.py` 将 `evaluation` 更新为 `pass`（`PROMPTFOO_REPORT_VERIFIED`）。公开 checker `status: pass`。
- Windows 适配：`evals/promptfooconfig.yaml` 的 `pythonExecutable` 改为 `../.venv/Scripts/python.exe`；官方 checker 读文件未指定编码，在繁体中文 Windows（cp950）下误报 `product_fit_gap: MISSING_OR_INVALID`，以 `PYTHONUTF8=1`／`python -X utf8` 运行解决，未修改 checker，已列为待反馈课程方的环境问题。依赖安装使用 uv（`uv venv` + `uv pip sync requirements.txt`），版本与 requirements.txt 一致。
- 参考资产：未使用 W1 checkpoint 或其他参考答案。
